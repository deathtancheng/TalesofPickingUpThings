## 快速开始：从 GitHub 拉下来怎么跑

### 0. 需要什么

| 依赖 | 要求 | 说明 |
| --- | --- | --- |
| **Node.js** | ≥ 22 | 后端零第三方包，只用原生 `http` + `fetch` |
| **Python** | ≥ 3.10 | 只有摄像头那条链路要用（YOLO） |
| **Ollama** | 任意新版 | 夜里妖物的脑子。**没有它游戏照样能玩**，只是不出剧情台词 |
| **摄像头** | 可选 | 没有也能完整玩完五层，游戏页上有「手动举物」 |

### 1. 拉代码

```bash
git clone <你的仓库地址>
cd local-ai-lab
```

### 2. 装 Python 依赖（只在要用摄像头时）

```bash
pip install opencv-python numpy ultralytics
# 想跑 ONNX 引擎再装 onnxruntime-gpu；默认用 .pt 引擎，不需要
```

> 仓库里**没有模型权重**（`.gitignore` 排除了 `*.pt`）。
> 没有自己训的 `best.pt` 时，程序会自动退回官方 `yolo11n.pt`，
> ultralytics 首次运行会自己下载一次（几 MB），联网即可。

### 3. 拉大模型

```bash
ollama pull qwen3:8b
```

### 4. 启动

**Windows：双击 `start.bat`**（自动检查 Ollama → 拉起摄像头服务 → 拉起 Web 服务 → 开浏览器）。

**macOS / Linux：**

```bash
bash start.sh
```

> 本机 Windows 上如果想用这个 sh 脚本（而不是 bat），
> 用 `YOLO_PY="D:/yolo-venv/Scripts/python.exe" bash start.sh` 指定装了 YOLO 的解释器。

手动启动（三个终端各跑一条，别加 `&`——后台进程会随终端关闭被回收）：

```bash
ollama serve                        # 终端 1（装完一般已常驻，可跳过）
cd yolo && python camera_server.py  # 终端 2（摄像头服务 5179）
node server.js                      # 终端 3（Web 服务 5178）
```

### 5. 打开页面

- `http://127.0.0.1:5178/public/game.html` —— 《拾物奇谭》游戏
- `http://127.0.0.1:5178/` —— 智能体工作台

### 6. 关掉

Windows 双击 `stop.bat`；macOS / Linux `bash stop.sh`，或各终端 Ctrl+C。

## 第一部分：本地大模型 + 智能体

**部署**：Ollama 0.34.0，模型 `qwen3:8b`（Q4_K_M，5.2GB），实测 100% GPU 卸载占 5.6GB 显存，
8GB 卡刚好够，还剩约 2.5GB 给 YOLO。

**智能体**：没用 Dify / n8n / 扣子，手写 ReAct 循环（约 60 行）——
模型返回 `tool_calls` → 本地执行 → 结果以 `role:'tool'` 塞回上下文 → 再问，最多 6 步。

**工具集**：`calculator`（白名单字符过滤，禁任意代码执行）、`get_current_time`、
`list_files`、`read_file`、`write_file`、`fetch_url`。所有文件工具限制在 `sandbox/` 内
（`path.resolve + startsWith` 防目录穿越）。

**实测**：一轮「查日期 → 算天数 → 写文件」3 工具 4 步，约 12 秒。

## 第二部分：YOLO 训练 + 实时推理

**环境捷径**：直接复用 ComfyUI 秋叶整合包的 Python（Py3.10.11 + torch 2.9.1+cu130），
用 `python -m venv --system-site-packages "D:/yolo-venv"` 建继承型 venv，
省掉约 4GB 的 torch 下载。

**训练结果**（yolo11n + coco128）：

| 指标 | 值 |
| --- | --- |
| mAP@0.5 | **0.7878** |
| mAP@0.5:0.95 | 0.6121 |
| 训练耗时 | 约 4 分钟 |
| 显存峰值 | 1.84 GB |

参数：`epochs=30 / batch=8 / imgsz=640 / amp / cos_lr / warmup 3`，理由写在 `yolo/train.py` 的 docstring 里。

**推理引擎对比**：

| 引擎 | 单帧耗时 |
| --- | --- |
| PyTorch (.pt) | 34.9 ms |
| PyTorch + FP16 | 41.0 ms |
| ONNX（同进程，4 线程） | 104 ms |
| ONNX（独立进程） | ~35 ms |
| **摄像头常驻服务** | **11.4 ms / 31.5 FPS** |

**踩坑清单**（每一条都是实测撞出来的）：

1. `workers>0` 在 Windows 上必崩（dataloader 多进程）→ 默认设 0。
2. GitHub Releases 的权重下不动 → 用 `https://ghproxy.net/<github-url>` 手动拉。
3. Python 往 stdout 打日志会让 Node 的 `JSON.parse` 失败 → 引擎信息改 `file=sys.stderr`，
   Node 侧再从后往前找第一段合法 JSON，双保险。
4. onnxruntime-gpu 的 CUDA EP 在本机起不来（ORT 1.23 要 CUDA 12 + cuDNN 9，本机是 cu130），
   装齐 DLL 并 `os.add_dll_directory` 注册后仍静默回退 CPU。**这条如实记录，没粉饰。**
5. ORT 与 PyTorch 同进程会线程打满：torch 占 24 个 OMP 线程，ORT 再开 24 个 → 486ms；
   `intra_op_num_threads=4` → 109ms。这个参数必须给。
6. **每帧打印的日志能把磁盘吃光**：`camera.log` 一晚上涨到 **33MB / 38 万行**，
   其中 99.99% 是同一句 `WARNING 'half' is deprecated`。
   两个原因叠加：
   - ultralytics 8.4 起 `half` 参数弃用，**只要传了（哪怕传 `False`）就报警**，
     且它用的是自家 `LOGGER.warning`，`warnings.filterwarnings` 压不住 → 改用 `quantize=16`，
     FP32 时干脆不传精度参数。
   - Windows 上客户端强断连接抛的是 `ConnectionAbortedError`（WinError 10053），
     **不在** `BrokenPipeError` / `ConnectionResetError` 里 → 覆盖 `handle_one_request` 统一兜 `OSError`。
   修完日志稳定在 184 字节，40 秒零增长。

**没上 VLM**：qwen3:8b 是纯文本模型，8GB 显存再塞 7B 视觉模型不现实。
走「YOLO 感知 → 结构化文本 → LLM 推理」，将来换 VLM 时工具接口不用动。

## 第四部分：自建 Harness

**Harness 是什么**：一句话，**Agent = 大模型 + Harness**。
模型负责想，Harness 负责让它想得下去——给工具、管上下文、记住上次的事、
危险动作前拦一道、把每一步摊开给人看。

第一部分那个 `/api/chat` 是写死的 ReAct 循环；这部分把它拆成可观测、可干预、可扩展的骨架。

### 六个模块

| 文件 | 职责 |
| --- | --- |
| `agent.js` | 核心主循环 ~400 行，只串钩子，不含任何业务 `if` |
| `lifecycle.js` | 四层 10 个钩子；**钩子（可干预）与事件（只读观测）是两套机制** |
| `provider.js` | 模型抽象，`for await (chunk of provider.chat())`，换模型不改主循环 |
| `tools.js` | `invoke()` **永不抛出**，失败也当普通结果返回（错误即消息） |
| `context.js` | 会话树（回退 O(1)）+ token 预算 + 模型自摘要压缩 |
| `memory.js` | 事实 + 情节两层记忆，关键词加权 + 30 天半衰，落盘 `sandbox/memory/` |
| `extensions.js` | 扩展 = 一组工具 + 若干钩子 + 一段系统提示，可热插拔 |

```
trace:start
  └─ turn:start
       ├─ model:start → model:stream* → model:end
       ├─ tool:start → tool:run → tool:end
       └─ turn:end
trace:end
```

### 三条设计纪律

1. **主循环里不许有 `if (某某业务)`**。要加能力就挂钩子或加扩展。
2. **错误即消息**。工具返回 `ok:false` 也照常塞回上下文，让模型自己判断。
3. **有状态在外，无状态在内**。turn 循环只认传进来的 messages，单轮可重放、可回退。

### 与 Pi 的两处分歧（刻意保留）

- **Pi 砍掉了权限弹窗，我保留**。这个 agent 要碰真实资源（文件、摄像头、以后的单片机），
  而且题目里写了「人类仅作启动子」——启动子不等于撒手不管。
- **Pi 面向短平快的编码会话，我要跑长任务**，所以加装了它没做的两样：上下文预算 + 长期记忆。

### 实测（HTTP 端到端，qwen3:8b）

| 场景 | 轮次 | 工具 | 耗时 |
| --- | --- | --- | --- |
| 计算 + 写文件 | 3 | 2 | 4.7 s |
| 查日期 + 算天数 + 写文件 | 4 | 3 | 12.1 s |
| 存长期记忆 | 2 | 1 | 5.0 s |
| **重置会话后回忆** | 2 | 1 | 3.5 s（短期清空，长期记忆命中） |
| 看摄像头（画面全黑） | 2 | 1 | 2.1 s（如实说没检测到，没编造） |
| bash 列目录（danger 级） | 2 | 1 | 7.4 s（权限门拦下 → 放行 → 执行） |

### 踩到的坑

6. **Ollama 要求 `tool_calls.arguments` 必须是对象**，传字符串报
   `Value looks like object, but can't find closing '}' symbol`——错误信息完全指错方向。
   对比实测：字符串版 400，对象版 200。方言差异收在 `provider.js` 里，主循环不感知。
7. **权限确认必须异步往返**：agent 等人类表态时是挂起的，前端必须在读流循环里
   `await` 用户点击再 POST 回去；先收完整个流再处理会死锁。

### 一个诚实记录的失败

问「距年底还有多少天」，模型构造了 `365-(10*30+1)`=64，正确答案 91。
calculator 忠实执行了它给的式子——**工具保证执行正确，不保证建模正确**。
Harness 能拦「哪些操作可做」，拦不住「思路错了」。这个教训直接决定了第五部分的架构。

## 第五部分：创意作品 —— 《拾物奇谭》

> 摄像头是手柄，YOLO 是输入解析，本地大模型是夜里的妖物，Harness 把这三样咬合成一个回合。

v4.0 起是**肉鸽 + 生存 + 策略 + 模拟经营**：你不再是"闯五层楼"，而是**在万物阁里一天一天活下来**。

```
迷宫（白天探索）──→ 阁楼（经营）──→ 夜袭（妖物上门）──→ 活到第二天
      ▲                                            │
      └──────── 天亮，回到昨天那一格接着走 ←────────┘
```

死了就结算：看你**活了多少天**，解锁一件遗物，下一局（周目）的妖物更硬。
v4.1 补上了三个"硬约束"：**香火**（献祭要烧香）、**歇脚处**（回阁要走到地方）、
**场景**（有事发生的房间强制过场）。

### ① 迷宫（肉鸽，毫秒级规则裁决，不等模型）

每天出门是一张新抽的 5×5 房间图。视野只有**十字五格**（自己 + 上下左右），
其余永远是雾，而且**每走一步，视野外的房间全部重新掷内容**——走过的地方不留图，
背地图这条路断了。三处是地标、永不移动：**阁门**（左下）、**下楼的梯**（右上）、
**歇脚处**（浅层 1 处 / 深层 2 处）。图例下有一条粗粒度导航（「梯 正东·不远」），
不然十字视野容易变成瞎猜。

房间种类：

- **拾物处**：举起身边的物件，把它收进背囊（识别越准、举得越大，品质越高）
- **妖物**：堵在门口，**跑不掉**——进去就得把它打散
- **陷阱**：在图上和空房长得一模一样，踩进去才知道（看得见的陷阱不叫陷阱）
- **箱笼 / 神龛 / 行脚商**：开运气、拜或砸（拜能得香）、挑货买（也卖香）
- **熔炉间**：举起东西丢进坩執，熔成一件属性随机的护符（装备的正路）
- **铜镜间**：照一照看清自己这一身，换回精神与术力
- **借宿**：分他一半干粮，回体力、加香火，代价是房钱
- **歇脚处**：歇口气、刮两炷残香，**从这里才能回阁**
- **梯子**：站上去可以**下潜**——越深妖物越凶、陷阱越多，精神也扣得越狠
- **空房**：不是空白。每次走进去都有一点小事（砖缝里的旧钱、别人落下的干粮、
  墙上的刻字、墙角窸窣一声），而且**每次都触发**

除普通空房以外，走进任何房间都会弹出一屏**场景**（场景图 + 旁白 + 选项），
处理完才能继续走——想看一眼就溜？门都没有。

**v4.3 的两条地图规矩**：视野只有十字，视野外每一步都在变（上面第一段）；
歇脚处是**地标**，浅层 1 处、深层 2 处，永不移动。

### ② 万物阁（模拟经营，策略的落点）

从歇脚处回阁，把拾来的东西变成夜里的底气，六间房随你营造：

| 设施 | 作用 |
| --- | --- |
| 货仓 | 背囊容量（满级 6 → 18 格） |
| 丹房 | 每天一顿热食（补饱食） |
| 卧房 | 每天一觉（补精神） |
| 书斋 | 参悟心得（永久生效） |
| 祭坛 | 把物件**炼成精怪**，也是**存香的地方**（上限与每日购买量都随它涨） |
| 门面 | 夜里自动进账铜钱 |

**精怪**是这套经营的核心：仓库里的物件在祭坛上炼成精怪，喂食升级，
属性决定本事（灼烧 / 回气 / 削反击 / 挡首击 / 看破架势……），夜里自动替你出手。
铜钱只有一份——盖丹房还是盖祭坛，今晚之前必须选一个。

### ③ 夜袭（回合制献祭，妖物由本地大模型扮演）

入夜妖物顺着阁墙爬上来。你把物件举到摄像头前献祭，由它裁定能不能伤到它——
你献一祭，它必定还手；每第三回合它还会放**蓄力一击**（反击翻倍）。

- **献祭要烧香**：一祭一炷，香尽点不着火——只能改用咒术（费术力，不费香）。
  香从经营里来：每晚 +1、神龛、歇脚处、箱笼、阁里买，祭坛决定上限
- 举得**越近越大**（占画面比例）→ 威力越高
- 识别**越准**（置信度）→ 打得越实
- 物件**属性克制**妖物 → 伤害接近翻倍（水克火、土克水、火克金、土克电、火克知）
- **连击**：连续克制伤害越叠越高，被打断清零
- **狂暴**：妖物体力低于 35% 会伤重发狂——反噬狠一半，速攻要付代价
- **架势**：每几回合换一次姿态，只有特定属性的祭品/咒术能破防
- **装备**：白天捡的护符在迷宫和夜战里都实打实加攻防暴——
  以前只有夜战算，v4.1 起白天砸妖物也算

摄像头取景框平时**不在画面里**，要献东西的时候（夜战、或走进等你举物的房间）
才抬起来——平时视线留给地图和阁楼。

### ④ 生存：饱食 + 精神 双条

| 命线 | 消耗 | 见底的后果 | 怎么补 |
| --- | --- | --- | --- |
| 饱食 | 走一格 -3、夜战一回合 -2 | 低于 25 伤害 ×0.75；归零每步掉 3 体力 | 丹房进食（每天一次） |
| 精神 | 遇妖、踩陷阱、下潜 | 低于 20「失魂」：迷宫迷路、夜里手不听使唤 | 卧房歇息（每天一次） |

于是「攒钱盖房」和「今天多走两格」变成同一个钱包里的取舍。

### 核心设计：规则归代码，叙事归模型

这是被第四部分那个「距年底天数」的教训逼出来的。

如果让 8B 模型自己算伤害，它每回合给出的数字都会漂，血条就成了随机数，
玩家的策略（挑大件、挑对属性）也完全落空——因为模型感知不到公式。

所以规则层（`src/game/rules/`，三层四文件：`core.js` 纯数值与算式 / `world.js` 万物阁·香火·迷宫·精怪·房间 / `run.js` 本局状态机，外加 `index.js` 汇总出口）把所有会漂移的东西锁成纯函数：
属性判定、克制表、威力曲线、暴击、反击、饱食扣减、香火收支、设施造价、精怪加成。
模型拿到的只有**已经算好的结构化裁决**，它的活儿只是把数字翻译成故事。

而且只有**夜战**惊动模型：迷宫与经营整条链路是毫秒级纯函数——
一格 13 秒的模型叙事会把探索节奏拖死。规则归代码，叙事归模型，**节奏归玩家**。

十只妖物都有水墨立绘（`public/img/`，按属性共用五张图）：
灰烬书童、苔痕守井、纸札判官、灯下人、焦尾琴奴、盐井蛙母、锈刃将军、
拾骨老妪、雷纹傀儡、万物之影。

### 用上了前面四部分的哪些东西

| 部件 | 来自 |
| --- | --- |
| 妖物的脑子 | 第一部分：Ollama qwen3:8b |
| 看懂你举的是什么 | 第二部分：YOLO 实时检测（31 FPS） |
| 回合流程、工具、记忆、权限门 | 第四部分：Harness |
| `model:start` 钩子注入今夜妖物的身份 | 第四部分：钩子的**干预**能力（不是事件观测） |
| 一局结束后战绩写进长期记忆 | 第四部分：`memory.js` |

游戏是作为一个**扩展**（`src/harness/extensions/quest.js`）挂上去的，内核一行没改。
这正好验证了第四部分搭扩展机制时想要的东西。

### 一次真实回合的内部流程

```
玩家举起水杯
   │
   ├─ YOLO 识别 → cup, conf 0.92, 占画面 35%
   │
   ├─ 节点侧组装 goal → 交给 Harness
   │
   ├─ model:start 钩子 → 注入「你是今夜来犯的灰烬书童，属性火」
   │
   ├─ 模型调 quest_resolve(label, conf, area_ratio)
   │      └─ game-rules.js 纯函数算出：水·克制·71 伤害·S 级
   │
   ├─ 模型读裁决 → 写 60~150 字剧情
   │
   └─ trace:end 钩子 → 一局收尾时，战绩写进长期记忆
```

### 实测：自动游玩（`node scripts/game-auto.js`）

人类只按一次启动键，剩下的 Harness 自己跑完：

```
— 第 1 发 · 第 1 层 灰烬书童（火）· 献上 bottle（水克火）
   水 · 克制 · 69 伤害 S 级
   「那瓶液体在空气中泛起一丝潮湿的寒意，仿佛从深井底部涌出的冷泉…」
   ★ 妖物退了 → 第 2 天
   …
★★ 守到第 10 天。共献祭 30 件，耗时 68.9s，旅人剩余体力 65
```

| 情况 | 伤害 |
| --- | --- |
| 属性克制（占画面 35%） | 71 |
| 属性被压制 | 19 |
| 无克制 | 29 |

一局结束后自动沉淀的长期记忆：

```
拾物奇谭·2026-10-02 → 守到第 10 天；共献祭 30 件，旅人剩余体力 65；
                      最狠的一击是 bottle（水 68 伤害 S 级）
```

### 这一路上修掉的三个模型毛病

1. **妖物自己编了个名字**「玄影」，其实它叫「灰烬书童」。
   修法：用 `model:start` 钩子在每次请求前动态注入今夜妖物的身份。
   （顺带给内核加了一行——让 `model:start` 的返回值生效，之前发完就丢了。）
2. **每回合说同一句话**。修法：每回合随机指定一个切入角度
   （从声音 / 气味 / 触感 / 光线 / 一段旧回忆写起）。
3. **写战报时编造回合**。让它写战报，它编出了 10 个回合——实际只打了 3 回合。
   修法：加 `quest_log` 工具返回**真实**回合记录，并规定战报里的每个数字必须能在记录里找到出处。
   修完再测，战报与存档逐条对得上。

## 怎么跑

**只想玩游戏：双击 `game.bat`**（确保 Web 服务在跑 → 打开游戏页）。

**全都要：双击 `start.bat`**（自动检查 Ollama、拉起摄像头和 Web 服务、
游戏页 + 智能体工作台都打开）。也可以带参数只开一个：
`start.bat game` / `start.bat agent`。

结束运行 `stop.bat`。

> 没有 exe。这项目是 Node + Python 脚本，不打包成 exe——
> 两个 bat 就是它的"启动器"，双击即用。

手动启动：

```bash
# 1. Ollama（模型已拉过就不用再跑）
ollama serve
ollama pull qwen3:8b

# 2. 摄像头 YOLO 服务（第五部分要玩就得开）
cd yolo
D:/yolo-venv/Scripts/python.exe camera_server.py \
    --weights runs/detect/runs/coco128_yolo11n/weights/best.pt

# 3. Web 服务
node server.js          # → http://127.0.0.1:5178
```

> 别用 `node server.js &` 后台启动 —— 进程会随终端关闭被回收（本机实测过）。
> 要么独立窗口，要么直接用 bat。

然后：

- `http://127.0.0.1:5178/public/game.html` —— 《拾物奇谭》
- `http://127.0.0.1:5178/` —— **智能体工作台**（对话、YOLO 视觉面板、🧩 Harness 工作台）。
  智能体没有单独的开关——打开这个页面它就在了，左边输入框直接使唤，
  它会真的去调工具（算数、读文件、识图、动摄像头）。夜里上门的妖物也是它扮的。
- `node scripts/smoke.js` —— 后端冒烟（起服务 → 检查关键接口）
- `node scripts/smoke-frontend.sh` —— 前端冒烟
- `node scripts/e2e-v40.js` —— v4 机制验证（迷宫 / 生存 / 经营 / 夜袭 / 结算，不走模型）
- `node scripts/e2e.js "目标"` —— Harness 端到端
- `node scripts/game-auto.js` —— 自动游玩演示（人类只按一次启动键）
- `node scripts/game-play.js cup 0.9 32` —— 单回合命令行试玩

**没有摄像头也能玩**：游戏页上有「手动举物」按钮，能完整玩下去。

**要拿去演示给人看**：见 [`DEMO.md`](DEMO.md) —— 里面有 5 分钟演示脚本、
每天该举什么、故障预案，以及对方可能追问的问题怎么答。
